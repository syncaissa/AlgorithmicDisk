# Paper → code map

Every number in the paper comes from a JSON file in `results/`, produced by one script here, and every table is
generated from that JSON by `paper/make_results.py`. This map lets you go from any table or figure in
*AlgorithmicStorage_paper.pdf* to the command that produced it and the file it reads.

**One-command check without training:** `python3 verify.py` opens every shipped `.adisk`, regenerates every object
from its Seed with the shipped engines and checks the sha-256 in each Manifest (Tables 2, 5, 8, 9, 10, 13).
**Quick suite:** `./run_tests.sh` runs everything in the table that needs no long training (~45 min) and diffs
against `results/` with `compare.py`.

**What will and will not match exactly.** Regeneration is bit-exact by construction: every object must come back with
its recorded sha-256 on any machine, or something is wrong — please report it. Seed *sizes* match exactly when the
shipped engines are used. If you delete an `engine_*.json` and retrain, Seed sizes change by a few percent (random
initialisation, float summation order) and objects still regenerate bit-exactly. Timings are from one Xeon core at
2.5 GHz and will differ. Two rows are not reproducible byte-for-byte: `ideaBrainStormFile.txt` in Table 5 was a
snapshot of the research log (its object is still on `realfile.adisk` and is regenerated by `verify.py`), and
`rev3_5pct.txt` is a fresh random 5 % revision in each of `editaware.py` and `retrieval.py`.
